# 管理画面の使い方

本書は、日常の運用で管理画面を利用するための基本的な操作方法を説明します。

## 1. ログインとアカウントの保護

### 通常のログイン

1. 患者画面の「管理画面」ボタンを押し、管理者パスワードを入力します。
2. 今回指定のパスワードのみ運用では、そのまま管理画面へ進みます。現在のパスワードを継続するための移行はサーバ管理者が事前に行います。二段階認証が有効なアカウントで確認画面が出た場合だけ、5分以内に6桁コードを入力します。
3. 管理者ログインの有効期間は **15 分**です。期限切れ・失効時は再ログインします。設定、問診結果、エクスポート、ダウンロード等にも管理者認証が必要です。
4. 登録・ログイン・再認証に成功した TOTP は、同じ 30 秒枠で再利用できません。直後の操作が拒否された場合は、次のコードに変わるまで最大約 30 秒待ってから入力してください。

### 初期登録とログインできない場合

- `admin` の既定パスワードや、固定の非常用パスワードでは登録・復旧できません。
- 新規環境は「初期登録」、パスワードや Authenticator を失った場合は「専用資格情報でアカウントを復旧」を選びます。サーバ管理者がオフラインで発行した、対応する一回限りの資格情報が必要です。
- 専用資格情報は既定 15 分で期限切れになり、使い終わると再利用できません。**発行時点で既存のログインが失効し、復旧を進めるまでアカウントはロックされます。** 作業時刻をサーバ管理者と合わせてください。
- 新しいパスワードは **12 文字以上、UTF-8 で 72 バイト以下**にします。日本語等は 1 文字が複数バイトになるため、長さの上限に注意してください。
- パスワードのみ運用の新規登録／回復はパスワード設定後に管理画面へ進みます。MFA登録画面が出る設定の場合は、QR コードを Authenticator で読み取り、10 分以内に新しいアプリの 6 桁コードを確認します。**QR の表示だけでは登録は完了しません。** 確認完了まで管理画面は利用できません。
- QR／秘密値は後から再表示できません。登録の中断・期限切れ・資格情報の紛失時はサーバ管理者に相談してください。使用済み資格情報の再入力や、旧リセット機能では復旧できません。
- 二段階認証の必須／任意はサーバ設定に従います。任意でも登録済みアカウントのコード要求は維持されます。秘密値の欠落・復号エラー時に二段階認証が自動で無効になることはありません。

発行・バックアップ・移行の手順は [セットアップ手順](<../internal_docs/admin_system_setup.md>) を参照してください。実 DB や鍵を削除・置換して初期化するのではなく、保全後に専用の復旧手順を利用します。

### 「セキュリティ」での変更

1. 現在のパスワードで再認証します。二段階認証を登録しているアカウントでは未使用のAuthenticatorコードも必要です。再認証は 5 分有効です。
2. パスワードを変更したら、新しいパスワードでログインし直してください。**二段階認証は維持されます。** 古いログイン資格情報は失効します。
3. 「Authenticatorを登録・再登録」では、新しい QR を読み取り、5 分以内に新しいアプリのコードを確認してください。確認が終わるまでは既存の Authenticator が有効です。
4. 必須ポリシーでは二段階認証を無効化できません。任意ポリシーでも管理者ログインと直近の再認証が必要です。旧 TOTP モード切替や非常用パスワードの画面／API は使用しないでください。

### 操作時の通知について
- 各ページで保存やエラーが発生した際は画面右上に統一デザインの通知が表示され、必要に応じて「再試行」などの操作ボタンを押せます。
- 保存処理やモデル一覧取得など継続して参照したい結果はページ内のステータスバナーにも並びます。疎通テストの手動実行結果は通知のみで確認できます。
- 管理者としてログイン中に問診が完了すると、外観・通知設定で OS 標準通知を有効にしている場合はブラウザのデスクトップ通知でもお知らせされます。
  - 有効化すると初回にブラウザから通知許可を求めるトーストが表示されます。許可すると、FCM Pushの設定済み環境では管理画面を閉じていてもOS標準の通知が届きます。
  - 通知の有効/無効は端末（ブラウザ）ごとに保存されます。他の端末やブラウザには影響しません。
- 無効のままでも画面右上の通知で完了を確認でき、通知の「問診結果を確認」ボタンから一覧画面を開けます。

## 2. メイン画面（ダッシュボード）の確認ポイント
- ログイン後は左メニューの「メイン」が自動的に開きます。ここでは初診・再診を問わず最新の問診データをまとめて確認できます。
- 画面上部の表には、問診セッション（初診/再診）の最新10件が表示されます。
  - 各行には患者名・受診種別・問診日時が並び、行をクリックすると詳細画面に遷移します。
  - 「出力」ボタンから PDF / Markdown / CSV を個別に出力できます。Markdown はワンクリックでクリップボードにコピーされます。
  - 10件を超える履歴や検索を行いたい場合は、左メニューの「問診結果一覧」を利用してください。
- 表の下には以下の情報カードが並びます。
  - **使用中テンプレート**: 現在登録されているテンプレートIDと、初診/再診で利用できるかどうか、既定テンプレートIDが確認できます。
  - **データベース**: CouchDB を利用中か、SQLite を利用中か、エラーが発生していないかを色付きのタグで表示します。
  - **LLM**: 最新の通信状況（疎通良好/接続エラー/確認待ち/無効）と、設定中のプロバイダ名・モデル名・接続先URLを表示します。
    - 状態は疎通テストまたは実際のLLM呼び出しが完了したタイミングで更新されます。ログインだけでは課金を伴う疎通処理を実行しません。
    - ツールチップでは直近の更新日時と結果の詳細を確認できます。赤表示の場合は設定内容を確認してください。

## 3. 外観・通知設定の変更
1. 左メニューの「外観・通知設定」を開きます。
2. 表示名・メッセージ・ブランドカラー・ロゴ・通知設定の各セクションを必要に応じて編集します。
3. 表示名・メッセージ・カラー・ロゴは入力後数秒以内に自動保存され、患者画面と管理画面へ即時反映されます。通知設定は端末（ブラウザ）ごとに保存され、初期状態では無効です。

### 3-1. 表示名とメッセージ
- システム表示名は患者向け画面と管理画面で共通して利用されます。未入力の場合は既定値（問診メイト）が表示されます。
- 表示名が長い場合でもヘッダー内で自動的にフォントサイズが調整され、一行表示を保ちます。
- 「問診開始画面のメッセージ」「完了画面のメッセージ」はそれぞれ患者画面の案内文です。内容を変更すると自動保存され、即座に反映されます。

### 3-2. ブランドカラー
- パレットから既定の色を選ぶか、カラーピッカーで任意の16進カラーコードを指定できます。
- 変更すると自動で保存され、主要ボタンやアクセントの色がまとめて更新されます。

### 3-3. ロゴ / アイコン
1. 「クリニックのロゴ/アイコン」で **PNG／JPEG／WebP の単一フレーム画像**を選択します。入力・再エンコード後とも **512 KiB 以下**、**4,000,000 ピクセル以下**が上限です。SVG／HTML／アニメーション画像は利用できません。メタデータは除去されます。
2. アップロードが成功すると「表示範囲を調整」ボタンが利用できます。ボタンを押すとモーダルが開き、青い枠をドラッグして表示範囲を調整できます。
3. ファイル名に空白や日本語が含まれていても自動的に安全な名称へ変換されるため、特別な事前調整は不要です。
4. モーダル内では数値入力欄や「全体」「正方形」ボタンも利用できます。モーダルを閉じても調整内容は自動保存され、数秒以内に患者画面ヘッダーや管理画面に反映されます。

### 3-4. 通知設定
- 「OS標準通知（ブラウザ通知）」のスイッチで問診完了時にデスクトップ通知を表示するか切り替えられます。設定は端末ごとに保持され、既定ではオフです。
- 有効化すると通知許可を促す案内が表示され、ブラウザ上で許可した場合のみ OS 標準の通知が届きます。ほかの端末には影響しません。
- FCM Pushを設定していない環境では、管理画面を表示している間だけ60秒間隔で完了状況を確認します。常時接続は行いません。
- 無効化しても、管理画面を表示中は画面右上のトースト通知を確認できます。ブラウザ通知が不要な運用時に活用してください。

## 4. 問診テンプレートの管理
1. 左メニューの「テンプレート」を開きます。
2. テンプレートを作成・編集し、必要に応じて問診項目を追加します。
   - 各項目には画像を添付できます。形式・サイズ・画素数は「ロゴ / アイコン」と同じ制限です。アップロードした画像は設定画面でプレビューされ、患者画面では質問と補足説明の下に大きく表示されます。
     - プレビュー画像をクリックするとモーダルで拡大表示されます。
     - 「画像を削除」ボタンを押すと確認ダイアログが表示され、承認後に削除されます。
     - 画像を設定した項目は項目一覧のラベル右側に画像アイコンが表示されます。
   - 患者基本情報（氏名・よみがな・住所・電話番号など）は固定UIで必須入力され、テンプレートの項目一覧には表示されません。
   - 選択肢ごとに条件分岐の追加入力欄を設定でき、特定の回答時のみ表示される追加質問を最大2階層まで追加できます。
     - 各選択肢の右側に表示される「？」アイコンにマウスを乗せると「追加質問を追加」の案内が現れ、クリックで編集モーダルが開きます。モーダルを開いた直後から新しい追加質問の入力欄が表示されるため、すぐに内容を編集できます。
     - 問診項目一覧に表示された追加質問をクリックすると、該当する追加質問を編集するモーダルが開きます。
   - 患者画面では条件を満たした場合に通常の質問としてその場に差し込まれ、特別な表示は行われません。
   - 追加質問を設定した選択肢には「枝」マークが表示され、項目一覧では追加質問が一段下げて表示されます。
   - 入力方法としてスライドバーを選択でき、最小値と最大値を設定可能です（既定は0〜10）。
   - 「性別で表示を制限」のチェックボックスをオンにすると、性別のプッシュボタンが表示されます。ラベルは「男性のみに質問」「女性のみに質問」となり、どちらかを選択して対象性別を指定できます。
   - 「年齢で表示を制限」をオンにすると、年齢範囲スライダーで表示対象の年齢帯を設定できます。スライダーは表示範囲の横幅の 2/3 で中央揃えで表示されます。患者の情報が条件に合致しない場合、その質問は表示されません。
3. 右上の「プレビュー」で患者画面での表示を確認できます。

### 4-1. テンプレート一覧の操作
- 一覧表の各行では以下の操作ボタンが利用できます。
  - **複製**: 既存テンプレートを新しいIDでコピーし、複製直後に編集画面へ切り替わります。
  - **リセット**: 標準テンプレート（ID:`default`）の行にのみ表示され、初期状態の内容へ戻します。
  - **名称変更**: 標準テンプレート以外の行で表示され、テンプレートIDを変更します。関連するサマリープロンプトや既定テンプレート設定も自動的に更新されます。
  - **削除**: 標準テンプレート以外の行で表示され、テンプレートと紐づく設定を完全に削除します。
- 標準テンプレートは削除・名称変更できません。編集内容を破棄したい場合は「リセット」を利用してください。

### 4-2. 郵便番号辞書の管理
1. 左メニューの「郵便番号辞書」を開きます。
2. 画面上部で辞書の利用可否、登録件数、元ファイル名、最終更新日を確認できます。
3. 日本郵便 KEN_ALL 形式のUTF-8 CSVを選択し、「アップロードして更新」を押すと、患者画面の住所自動入力に使う辞書が更新されます。
4. 辞書が未登録、検索失敗、該当なしの場合でも、患者画面の住所欄は手入力できます。自動入力の失敗だけで問診が止まることはありません。

## 5. LLM 設定
1. 左メニューの「LLM設定」を開き、利用するプロバイダや接続先を設定します。
2. 設定保存時に自動で疎通テストが行われ、結果が通信状況として記録されます。
3. 追質問やサマリ作成を利用する場合は、この設定が有効である必要があります。
4. モデル名の入力欄右側にある「疎通テストを実行」で手動テストすると、結果は画面右上の通知で確認できます。`ollama`、`lm_studio`、`openai` では「使用可能なモデル一覧を取得」ボタンが表示されます。`gcp_vertex`（Google Cloud Vertex AI）はモデル名を直接入力して疎通を確認します。
5. 「Google Cloud Vertex AI」等の非公開アダプター固有のプロバイダーは、対応する機能が利用可能な環境でのみ使います。基盤側の確認は [非公開アダプター](<../private/cloud-run-adapter>) の担当者に依頼し、JSON 秘密鍵を管理画面へ入力・保存しないでください。
6. LLM設定、プロバイダ情報、モデル一覧、疎通テスト、詳細な通信状態は管理者ログイン後だけ取得できます。画面が401を表示した場合は再ログインし、403の場合は権限・セキュリティ設定も確認してください。
7. 保存済みの API キーは表示・エクスポートされず、設定済みかどうかだけ確認できます。変更時のみ新しい値を入力します。接続先はサーバ管理者が許可した範囲を使用し、URL 検証の拒否を迂回しないでください。
8. 設定を保存しても、過去の問診履歴を自動で LLM へ再送・再要約しません。動作確認には新しい合成データの問診を使い、既存の実患者情報を試験目的で再送しないでください。

## 6. 問診結果の確認
1. 左メニューの「問診結果」で送信済みセッションを確認できます。
2. 各行のアイコンから PDF / Markdown / CSV 形式で結果をダウンロードできます。
   - PDF は患者情報・質問・追質問を罫線付きのフォームとして配置し、紙の問診票に近いレイアウトで出力されます。
   - Markdown は患者情報（氏名・よみがな・生年月日・住所・電話番号など）を冒頭に整理した形式で出力し、YES/NO形式の回答も「はい」「いいえ」で表示されます。
   - 管理メニューの「PDFレイアウト」設定から、必要に応じて従来のシンプルなレイアウト（レガシー）へ切り替えできます。

## 7. データベース/LLM の稼働状況表示
- 「メイン」画面のカードで、現在利用中のデータベース種別・LLM疎通状態・モデル名を一目で確認できます。
  - 緑「DB:CouchDB」: CouchDB に接続できています。
  - 青「DB:SQLite」: CouchDB 未使用で SQLite を利用しています。
  - 赤「DB:接続エラー」: データベースに接続できていません。
  - LLM カードでは疎通状態（疎通良好/接続エラー/確認待ち/無効）と設定中のモデル名・接続先が表示されます。
- 画面上部のヘッダーにも従来通りバッジが表示され、どのページにいても状態を確認できます。バッジにマウスを乗せると最新の確認時刻と結果が表示されます。

## 8. さらに詳しい情報
システム全体のセットアップ・専用資格情報の発行・移行手順は [管理者セットアップ手順](<../internal_docs/admin_system_setup.md>) を参照してください。本変更の確認はローカルの隔離環境と合成データで実施しており、本番への反映・実 DB の移行を実施済みとするものではありません。


## 9. 設定と問診データのバックアップ

これらの操作は管理者認証が必要です。通常のエクスポートは DB 全体のバックアップではありません。**管理者アカウント・TOTP・秘密鍵・LLM API キー・患者セッションの操作資格情報は含まれません。** 移行先での管理者登録と秘密情報設定はサーバ管理者が別途行います。

- **テンプレート設定のエクスポート/インポート**
  - 「テンプレート」画面から、テンプレート・各種プロンプト・秘密値を除いた LLM 設定・ブランド設定・項目画像をダウンロードできます。
  - パスワード指定による暗号化 JSON も利用できます。インポート先が対応している場合は、同じパスワードで復号します。
  - 対応バックエンドでは「既存に上書き（merge）」または「入れ替え（replace）」を選びます。入れ替えは現在の対象データを置き換えるため、事前にバックアップを取得してください。
- **問診データのエクスポート/インポート**
  - 「問診結果」のカードから選択した対象を JSON でダウンロードできます。個人情報を含むため、保存先・アクセス権限・保管期間を院内方針に従って管理します。
  - 対応バックエンドでは追加（merge）または全件入れ替え（replace）を選べます。入れ替え前には対象とバックアップを必ず確認してください。
- **インポートの制限**
  - ファイルは 5 MiB 以下、レコード数は原則 100 件までです。画像には 512 KiB／4,000,000 ピクセル等の制限も適用され、暗号化ファイルでも検証を省略しません。
  - 検証済みのデータを一括反映する atomic import hook がないアダプターでは、**HTTP 501** で停止します。CouchDB／Firestore 等を含め、可否はバックエンドの対応状況に依存します。未対応時に一部だけ書き込む処理は行いません。
  - 501 は、ファイルを小さくする・DB を削除する・認証を無効にすることで解決するエラーではありません。サーバ管理者に対応状況を確認してください。

## 10. API連携とChrome拡張機能

左メニューの「API連携」で、APIエンドポイント、ヘッダー名`X-MonshinMate-Api-Key`、APIキーの有効状態を確認できます。
APIキー本体はSecret Managerで管理し、管理画面からは表示、生成、変更、削除できません。

院内運用では、`medical-document-creator-extension`に統合した「患者情報」の「問診」タブを使用します。
拡張機能はCLINICSの表示患者が変わると、`POST /patient-summaries`で氏名と生年月日が完全一致する確定済み履歴を自動取得します。
取得した問診は画面のメモリだけに保持します。

最新の問診は、確認画面を通してCLINICSの患者基本情報と表示中カルテへ登録できます。
問診が初診の場合は、`POST /patient-summary/pdf`で帳票を取得し、患者書類として追加できます。
基本情報は非空のカナ、郵便番号、住所、電話番号だけを対象とし、氏名、生年月日、性別は更新しません。

連携用の固定 API キーはサーバ管理者がアクセス制限された秘密情報管理で保管し、承認された連携クライアントだけに適用します。管理画面・Chrome storage・ログへ保存せず、ローテーション時は連携先への反映も管理者に依頼してください。基盤固有の対応は [非公開アダプター](<../private/cloud-run-adapter>) の担当範囲です。

[XPath 式スタンドアロン拡張](<../extensions/patient-summary>) は互換性確認用で、新規の院内運用には使用しません。
詳細は [セッション API](<session_api.md>) と [Chrome 拡張の説明](<chrome_extension.md>) を参照してください。
